## 1. Task description

A homeowner is plumbing a house water system: storage tanks feed jet pumps, and the pumps
feed pressure vessels. Before ordering, they want a fitting take-off for every pipe run.
The agent receives six files under `/app/input`:

- the kit's ports as the retailer listed them (`components.csv`, 20 ports);
- the makers' published port tables with dated revisions (`spec_sheet.md`);
- every pipe run with its length, including runs since re-routed (`connections.csv`, 27 runs);
- the supplier's catalogue with stock status (`fitting_catalog.csv`, 21 rows);
- the governing rules (`takeoff_rules.md`, Rev C, T1–T10);
- the output contract (`submission_format.md`).

It must deliver three files:

- `/app/fitting_register.csv`: one row per connection taken off, with the catalogue fitting and its kind (`COUPLER`, `REDUCER`, `ADAPTER` or `UNRESOLVED`);
- `/app/takeoff_note.md`: a short note for the supplier with the reducer and coupler counts, naming each unresolved connection;
- `/app/results.json`: three counts and the pipe total.

The population is not handed over. Which runs are taken off (3 of the 27 are withdrawn by
the `replaces` column) and each port's size must both be derived:

- A size comes from the maker's table revision **in force on 2026-09-15**. Some revisions take effect exactly on that date, others later, and publication dates are irrelevant.
- The retailer's `listed_size_in` is never used.
- DN sizes are mapped to inches.
- Sizes are compared numerically across fraction, decimal and DN notation.
- Only `STOCKED` catalogue rows can be selected, with each end matched on both size and thread.

The key has 24 rows: 11 reducers, 3 couplers, 8 adapters and 2 unresolved (C-10, C-24), with 181.5 ft of pipe.

## 3. Declarations

- **Reward shape:** binary. Every check is core, and the reward is 1.0 only when all 7 pass, else 0.0. This is declared in `task.toml` `metadata.reward_shape` and implemented in `tests/score.py`.
- **Checks (7, all core, all deterministic):**
  - `register_header`: tolerant regex on the first line.
  - `register_table`: `table_equals` over all 24 rows, with the ordered population lock and the closed column set.
  - `results_figures`: `object_equals` over the closed key set; counts exact, total within 0.01.
  - `note_reducer_count` and `note_coupler_count`: the label and the number in the same sentence, either order, digits or words.
  - `note_unresolved_C-10` and `note_unresolved_C-24`: the ID and "unresolved" in the same paragraph, with no other connection's ID between them.
- **Checks files:** `tests/verifier.json` is what the engine, `score.py` and `test_outputs.py` load. `tests/manifest.json` is a byte-identical copy that exists only for the upload validator.
- **Judge:** none. There is no LLM rubric, so `JUDGE_MODEL` plays no part.
- **Network:** `network_mode = "public"`, an ENV-4 exception. With `"no-network"`, harbor's opencode agent could not install its own dependencies (`apt-get install nodejs npm` could not reach `deb.debian.org`; job `glm-smoke-day2`, `NonZeroAgentExitCodeError`). The agent also has to reach the model gateway. The verifier needs no network.
- **Deliverable carriers (PKG-13):** a CSV register is what a supplier order is picked from, a short markdown note is what a homeowner hands over, and a JSON totals file is the machine summary.
- **Evidence format:** harbor writes neither `verifier/reward.json` nor `verifier/verifier_summary.json`, and its `result.json` has no `model`, `overall_pass`, `reward`, `final_answer` or judge fields. These were added to each shipped run by `tools/annotate_rollout.py` without changing harbor's own fields. **CONFIRM** which annotator you used.

## 6. Probes and solvers (`tests/probe_suite.py`, 43 cases, `PROBLEMS: 0`)

- **Gold:** 1.0.

  - emptied register;

  - deleted note (all note checks).
- **Decoy solvers, one per wrong reading W1–W10:** every one fails, and only on the rows listed in §5.

  - majority class (every row REDUCER/NONE);
  - the instruction pasted as the note;
  - `connections.csv` copied as the register;
  - an empty workspace.
- **Note wording:** paraphrased, reversed, number-word, bulleted and CRLF+BOM notes pass. A wrong number, the number in another sentence, a missing ID, the ID in another paragraph, and a non-unresolved ID between an ID and "unresolved" all fail.
